Homepage Image Layout — Implementation Plan
Goal
Replace the current stacked, left-aligned, narrow image layout with a side-by-side two-column grid that fills the available content width. The desk photo (primary) and figurine photo (secondary) will sit next to each other in equal columns, with their captions underneath. The #featured-image heading will remain above the grid.

File 1: Homepage content (Markdown/HTML template)
File to find: The homepage source — likely index.md, index.njk, or src/index.md (or similar depending on the SSG structure). Look for the file containing the ## Featured image heading and the two .hero-shot divs.
Change: Wrap the two .hero-shot divs in a new wrapper <div class="hero-grid">. Do not change the individual .hero-shot or .hero-shot--secondary divs themselves — just add the wrapper.

File 2: assets/css/images.css
Changes needed:
A. Add the .hero-grid layout rule (new rule — add near the existing .hero-shot rules):
css.hero-grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 1rem;
  margin: 1.5rem 0;
  width: 100%;
}
B. Override .hero-shot max-width so each column fills its grid cell rather than being capped at 460px. Add this rule after the existing .hero-shot rule:
css.hero-grid .hero-shot {
  max-width: 100%;
  margin: 0;
  width: 100%;
}
C. Override .hero-shot--secondary max-width for the same reason (it's currently capped at 360px). Add this rule after the existing .hero-shot--secondary rule:
css.hero-grid .hero-shot--secondary {
  max-width: 100%;
  opacity: 0.9;
}
D. Add a responsive breakpoint so on small screens the grid stacks back to a single column:
css@media (max-width: 768px) {
  .hero-grid {
    grid-template-columns: 1fr;
  }
}

File 3: assets/css/base.css (optional, only if needed)
The .hero-shot base rule lives here with max-width: 460px. You can either remove that max-width from the base rule entirely (since images.css already has a scoped override via .hero-grid .hero-shot), or leave it and rely on the scoped override in images.css. Leaving it alone is the safer approach and the images.css override will take precedence due to specificity.
